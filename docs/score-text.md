# 小节文本格式

小节文本记录音符、节奏和奏法。每个小节占一行 UTF-8 文本，以 `MEASURE`（小节）开头；整首谱按阅读顺序逐行排列，下载文件为 `score.txt`。

```text
MEASURE time=4/4 tempo=120 | V0{@0:q:s1f0 @960:q:s2f1 @1920:h:r}
```

它表示 4/4 拍、四分音符 120 BPM：第一拍弹第 1 弦空弦，第二拍弹第 2 弦第 1 品，第三拍开始休止两拍。

## 表示与职责边界

- `scorelib/src/score.rs` 解析、格式化和校验 `M2`，并生成整谱 IR；Python 通过 `scorelib` 调用同一实现。
- 识别记录包含原谱位置、目标文本、人工修改及校对状态；项目由 `backend` 保存，研究脚本的阶段交换字段位于 `research/common/schema.py`。
- `guitarocr.score/2` 统一时间轴、音轨、谱表与音高语义。`score.json`、小节文本、MusicXML 和 GP5 从识别记录生成；格式限制由 `scorelib/src/music_exports` 处理。

音乐语义不加载模型或 Web 服务。产品的编辑和项目事务属于 `backend`；`research/inference/measures/result.py` 只组织研究任务的输出。保存原图、上下文与校对状态时使用项目 ZIP，单独文本或 `score.json` 不替代完整项目。

## 单位和声部

- `@数字` 是小节内的起点，四分音符为 **960 ticks**。WebUI 的小节设置显示四分音符拍数，保存时换算为 ticks。
- `V0{...}` 对应声部 1，`V1{...}` 对应声部 2；多个声部用 ` || ` 分隔，中间表示支持 `V0` 至 `V15`。整谱 GP5 导出按每轨两个声部分组，保持小节同步。
- 第 1 弦是最高弦；调弦数组同样按最高弦到最低弦排列。
- TAB 音符使用 `s1f3`；纯五线谱使用 MIDI 音高 `p67`；混合谱可写 `s1f3p67`。和弦用逗号分隔，如 `s1f0,s2f1,s3f0`。
- 钢琴等旋律乐器的 MIDI 编号表示实际发声音高。吉他、贝斯的编号不含变调夹升高的音程，变调夹由音轨单独保存和应用。谱号、乐器记谱移调和局部八度标记作为识别前文传入，导出时不再重复应用。
- 鼓轨中的 `p36` 表示 General MIDI 鼓件 36（底鼓），`p38` 为军鼓，`p42` 为闭镲。它的含义由轨道的乐器类型决定。

## 时值

| 标记 | 音符 |
| --- | --- |
| w / h / q | 全 / 二分 / 四分 |
| e / s / t / f | 八分 / 十六分 / 三十二分 / 六十四分 |
| q. / q.. | 附点 / 双附点四分 |
| e[3:2] | 三连音：3 个八分音符占 2 个八分音符时值 |

`r` 表示休止，`e` 表示空拍状态。`^` 重复同一声部前一个事件的音符与奏法，但使用当前事件的起点及时值；不能放在该声部首个事件。

## 常用字段与奏法

小节头部支持 `time`、`tempo`、`key`、`feel`、`bar`、`rep`、`alt`、`section`、`dir`、`from`。缺省拍号沿用上下文，完整乐谱应给首小节明确拍号。section 等文字使用 URL 百分号编码。

`feel=eighth` / `feel=sixteenth` 表示当前小节采用八分／十六分 swing。它是逐小节状态：正常目标中省略 `feel` 或显式写 `feel=none` 都表示直拍，不无限沿用历史 swing。默认并行模型从相邻图像读取演奏方式；识别失败的小节按有效拍号生成整小节休止占位并标为待检查。

音符级奏法放在圆括号中，例如 `s1f3(vib)`、`s2f5(hammer)`、`s3f2(pm,let)`。常见标记包括 tie、dead、vib、hammer、ghost、pm、stacc、let、accent、sl / ss 及 harm 等。事件级奏法放在尖括号中，例如 `<dyn:70>`。具体参数映射见 `scorelib/src/music_exports/gp5_techniques.rs`；使用 WebUI 谱面编辑时会保留已有奏法参数。

和弦名附着在对应拍上，例如 `<chord:F%23m>` 表示 F♯m，文字使用 URL 编码。指法图可同时写为 `<chord:C,diagram:1:x/3/2/0/1/0:-/3/2/-/1/-:->`；`diagram` 的四段依次是起始品、从低音弦到高音弦的绝对品位、每弦指法数字、横按。`x` 表示不弹，品位 `0` 表示空弦，指法 `-` 表示未标注、`0` 表示拇指。横按格式为 `品位/低弦索引/高弦索引`，索引从 0 开始，多条横按以分号分隔。页首和弦图保存在乐谱的标注库中，不会被当成第一拍的和弦。

局部八度标记写在受影响的每个事件上：`ottava:12` 对应 8va，`ottava:-12` 对应 8vb，`ottava:24` 和 `ottava:-24` 对应上下两个八度。例如 `p72<ottava:12>` 的实音仍是 MIDI 72，GP5 将它画低一个八度并显示 8va。乐器的整轨移调量另存在 `pitch_context.instrument_transpose`，取值为实音减记谱音高，降 B 调小号为 -2。

装饰音可以携带参数。例如混合谱的 `grace:f5p69:hammer:0:0` 表示第 5 品、MIDI 音高 69、击弦连接、拍前且非死音。纯 TAB 写作 `grace:f5:hammer:-:0`，其中 `-` 表示从 TAB 无法判断是否占拍；纯五线谱位置写作 `p69`，不会要求模型猜隐藏指法。死装饰音位置写作 `x`。`trill:f9` 保存 TAB 可见的辅助品位，纯五线谱只保留 `trill`。`trem:32` 保存谱面可见的震音细分时值。

Guitar Pro 原生渲染对照确认，装饰音播放时长和颤音播放速度不改变打印像素，因此不作为 OCR 目标。手工记录仍可使用完整形式 `grace:f5p69:32:hammer:0:0`、`trill:f9p73:32`；调用格式化函数时指定 `preserve_playback=True` 可保留这些参数。缺省导出采用三十二分细分。旧文件中的裸 `grace`、`trill`、`trem` 仍能读取；它们没有记录完整参数，导出时采用默认值。

`bend:prebendRelease:100` 等推弦标记按类型恢复上推、回落或预推轮廓；任意原始控制点曲线仍不能无损还原。GP8 会打印 `p`、`f` 等力度符号，但源文件逐音的 MIDI 力度不等于每个音都印有力度标记；当前 OCR 数据尚未按实际打印位置标注力度变化，导出时可用已有的 `dyn` / `vel` 手工补充。

小节内显式起点 `@960` 之前的空隙会在 GP5 中补休止，避免因 GP5 的隐式时序把音符前移。同一声部的重叠事件会报错。吉他、贝斯按调弦分配指法；钢琴及其他旋律乐器保留音高，鼓组使用打击乐通道。GP5 每轨最多七根弦、两个声部，每个声部最多七个同时发声的音符；整谱导出按声部、弦数及音域拆成同步音轨，并回读核对音符。

GP5 表示能力与原始谱面并非完全一致。请对照原图检查连线、反复、变调夹和复杂技巧。GP5 文字编码使用 cp936，无法表示的字符会列入 `.encoding.json`；小节文本保留原文。

## 格式与模型输出

语法有效不等于识别正确。模型输出结构无效时重试，多次失败后生成休止占位。结构有效但单声部占用超过当前拍号的小节保留全部音符并标为待核对；弱起／不完全小节不因时长较短报警，多声部各自计算，连音使用精确时值。这是 OCR 质量提示，不收紧历史 IR 的合法语义；识别清单以 needs_review、fallback_reason、review_measures 记录结果。标为待检查的小节必须确认后才能导出。小节文本文件本身不承载这些校对状态，因此备份工作时优先下载完整项目 ZIP。

格式前缀必须恰好是 `MEASURE`。未知或重复的小节头字段会报错，避免解析后静默丢失。原生 GP 的全空小节按打印的整小节休止生成标签。

默认模型读取当前及相邻小节图像，并接收批量识别后按谱序传播的拍号、调号；各小节文本独立生成，跨节延音统一处理。旧模型的 `CONTEXT` 表示上一小节摘要，不属于乐谱正文。谱面类型由版面检测传给 OCR，不由文本标记判断。

旧项目和旧格式文本仍可读取。内部表示与显示名称的转换由 `scorelib/python/scorelib/score_text.py` 处理，不改变模型训练协议。

通过 Python 库将单轨小节文本转为 GP5：

```python
from pathlib import Path
from scorelib.gp5.writer import write_targets_gp5
from scorelib.score_text import model_score_text

lines = Path("score.txt").read_text(encoding="utf-8").splitlines()
write_targets_gp5([model_score_text(line) for line in lines if line.strip()], "output/score.gp5", mode="tab")
```

`instrument` 可以指定 `guitar`、`bass`、`pitched` 或 `drums`，`tuning` 为调弦列表，`midi_program` 为从 0 开始的 MIDI 乐器编号。多轨项目应通过工作台导出，以保留音轨和谱表分组。

项目备份中的 `score.json` 使用 `guitarocr.score/2` 中间表示，保存统一时间轴、乐器、MIDI 音色、调弦，以及按音轨和谱表分组的小节与校对状态。`index` 对齐同时演奏的小节，`source_record` 对应原谱裁图；每个谱表可保存多个声部。页面流程自动识别总谱分组，各谱表独立读取音符并维护谱号、移调和延音关系。MusicXML 是可选导出格式，不参与模型的逐小节解码；GP5 将双谱表、超过两声部或超过七弦的内容拆为同步音轨。

`score.json` 在每条音轨和小节的 `pitch_reference` 中标明音高含义：旋律乐器为 `sounding`，吉他、贝斯为 `before_capo`，鼓组为 `percussion_key`。例如标准调弦第 1 弦空弦仍记录 `p64`，变调夹在第 3 品时实际发声为 MIDI 67。

各小节的 `pitch_context` 保存有效谱号、谱号八度、乐器移调量和局部八度标记的页面位置。版面检测负责定位，谱面信息模型负责读取，移调前文随谱表分别传递。没有印出的设置无法从图片恢复，可在谱面信息页填写“记谱移调”；更改后需要重新识别。GP5 保留音高和局部八度标记；明确的小号、萨克斯、圆号或英国管名称用于选择对应音色。其他整轨记谱设置保存在 `score.json`，GP5 中的显示还取决于音色及 Guitar Pro 的设置。

默认谱面信息模型读取打印的变调夹文字，也可在界面手动修改品位。小节模型使用变调夹上下文；吉他、贝斯的保存音高不含变调夹升高的音程，导出时由音轨的变调夹字段应用。

默认鼓组中，部分 MIDI 鼓件在 Guitar Pro 上打印为相同符号。训练标签将经原生渲染确认相同的 33 归为 37，34、39、40 归为 38，41 归为 45。相同符号无法恢复原文件选择的音色，导出采用上述代表鼓件。
