# 模型评测

项目使用一套版面模型和两套 OCR 适配器。以下结果来自固定权重的评测，权重与基座哈希见 [模型清单](../weights/manifest.json)。

## 数据与评测范围

主语料有 2,799 个曲源，按 2,400 / 199 / 200 划分训练、验证和测试。同一曲源的 TAB、五线谱、混合谱及增强图保持在同一划分。页面由 Guitar Pro 原生渲染，模拟扫描包括缩放、模糊、阴影、噪声和 JPEG 压缩。它们不能代表真实扫描件的全部情况。

模型按验证指标选择权重，独立测试不参与选择。小节 OCR 使用正确裁图；它的指标不包含页面定位误差。

## 版面检测

独立测试有 2,164 页，阈值 0.25，使用实际流程的后处理。四类为 TAB 小节、五线谱小节、混合谱小节和速度框。

| 测试图像 | 四类 AP@[0.50:0.95] | 小节数量完全正确的页面 |
| --- | ---: | ---: |
| 原生页面 | 95.30% | 2148/2164 |
| 同批页面的模拟扫描 | 95.67% | 2151/2164 |

原生测试中，TAB、五线谱和混合谱小节的 AP 分别为 98.90%、96.37% 和 98.27%。所有测试页面的谱面类型判断正确，但仍有漏框或位置偏差。验证集原生页面四类 AP 为 95.15%，小节数量正确 2322/2337 页。

完整定位、类型及数量指标见[版面评测记录](../weights/layout/evaluation.json)。

## 小节 OCR

独立小节测试固定 1,800 张正确裁图，每种排版 600 张，使用标注前文、batch 8、单次贪心解码，上限 2,048 tokens。

核心匹配要求整个小节的音符字段、节奏和元数据全部一致，元数据包括速度、调号、swing 和反复。完整匹配还要求规范化文本中的奏法等内容一致。

| 排版 | 核心匹配 | 完整匹配 |
| --- | ---: | ---: |
| TAB | 92.83% | 84.33% |
| 五线谱 | 85.33% | 74.67% |
| 五线谱＋TAB | 88.50% | 82.33% |
| 总体 | 88.89% | 80.44% |

原始输出约束合法率为 97.72%，41 个小节需复核。上述百分比按小节计数，不能用作逐音符准确率。

连续识别另取独立测试的 8 个曲源，共 1,860 个小节，每种排版 620 个。使用正确裁图、模型预测的前文，从首小节开始，batch 1、单次解码。核心匹配率为 95.32%，完整匹配率为 93.66%，4 个小节需复核。该组来源与独立小节测试不同，两组差异不能用于判断预测前文的影响。

额外的连续验证有 3,084 个小节：核心匹配 94.62%，完整匹配 87.22%，23 个小节需复核。原始核心匹配为 94.75%；其中 4 条的音符、节奏和元数据正确，但奏法参数无效，流程将它们替换为待检查的休止占位。

各排版、奏法和原始输出指标见[小节评测记录](../weights/measure_ocr/evaluation.json)。

## 整谱验收与限制

使用 PDFium 渲染页面，再自动定位、识别类型、读取谱头和小节并导出 GP5：一份真实扫描件的 17 个小节核心匹配，16 个完整匹配；一处下拨符号漏识别，标题、作者和速度正确。另一个保留曲源的三种原生排版各四小节，TAB 和混合谱均为 4/4，五线谱为 3/4。剩余小节整体低两个半音，语法检查没有捕获这个音高错误。

这些是少量流程案例。训练和测试主要覆盖规则吉他单轨谱，手写、透视照片、复杂多音轨总谱及同页混排需要更多验证。力度尚未按实际打印位置监督，训练语料中没有 trill 标签，任意推弦控制点也未完整覆盖。导出前仍需对照原谱检查音乐内容。
