# 模型评测

小节 OCR、谱面信息及整谱指标来自 2026-09-30 版；版面检测与 TAB 谱线计数更新至 2026-10-01 版。原始计数及条件见[共享 OCR 评测](../weights/score_ocr/evaluation.json)、[训练记录](../weights/score_ocr/training.json)和[版面评测](../weights/layout/evaluation.json)。

分数为 **F1 × 100**，同时计入漏识别和多识别。音符分要求声部、音高（纯 TAB 为弦品）、起点和实际时值同时正确；指法分要求弦、品、声部、起点和时值正确。和弦分要求名称及所属声部、小节和节拍位置正确。这些分数不表示整曲全部正确。

## 当前模型

谱面信息、分轨和小节识别共用一个 GLM-OCR 主模型；通过提示词切换任务。采用音乐词表、每批 64 小节、16,384 tokens 上下文、BF16；本轮实测选择 MTP 4。GGUF 使用同一主模型的 Q8_0 语言权重和 F16 视觉编码器，省略不执行的 MTP 层。

保留图像宽高比，按谱线尺度缩放并为小标注放大，竖排乐器名转正后单独放大。首小节上方的漏检短文字会补读；补读范围不进入小节，避免高音音符和连线被当成文字。小节读取当前及相邻图像后独立解码，拍号／调号批量读取并传播，跨节延音最后协调。页面先建立共同时间轴，钢琴双谱表和五线谱／TAB 配对归入正确声部。分组失败时放大谱行标签重读，并用其他页的一致结构恢复遗漏声部。

和弦名、指法图及奏法标注属于独立类型，不能作为移调依据。页眉和弦图保留为声部指法库，只有小节内实际读到的和弦才附着节拍。首次解码不使用 M2 语法约束；异常时重读，限制重复字段和无效和弦后缀。无法确认的标注保留并标记校对。

## 训练停止与推理速度

主任务训练使用 1,367,915 个样本，最后完整验证 loss 为 0.01712585。之后用 70,588 个同类乐器多轨、乐器标签及原任务复习样本补训结构与乐器上下文；其 9,282 项验证集最佳 loss 为 0.01595907。两项 loss 对应不同样本集，不能直接相减判断改进。主模型和草稿层均已停止训练。

MTP 在主任务模型上完成 1889 步，选择完整验证 loss 0.073259、token 一致率 98.70% 的草稿层。该一致率对应蒸馏时的主模型，不能当作 OCR 准确率。谱行补训后保留草稿层，并在最终模型上重新实测接受率、速度和识别质量。

单张隔离的 H100，顺序运行候选；同一批 384 条完整乐谱序列、20,965 个小节，batch 64、4 GiB KV cache、16,384 tokens 上下文。计时包含拍号／调号读取和小节识别，不含模型启动、PDF 渲染及版面阶段。

| 0 | 394.49 s | 0.800 s | 2.200 s | — | 96.89 |

选定引擎在该机器上的启动耗时为 27.3 秒，另于上表计时。工作台和服务端会复用已加载的模型。

选定配置相对同一新主模型关闭 MTP，耗时减少 11.29%。选择同时要求音符、指法及奏法分不超过预设退步容差。MTP 加速主模型认可的输出，不负责纠正视觉识别。

这些语料包含原生排版、组合谱和模拟扫描；不代表任意拍照或手写乐谱的准确率。Linux H100 的运行验证也不等于 Mac 或手机真机验证。

## 部署运行

GGUF＋ONNX 在 16 份留出整谱、840 小节上完成实际运行：音符与节奏 99.04，同一批输入的原生模型为 99.01；和弦名称＋节拍 99.90，流程失败 0。这是部署兼容检查，完整能力以上面的留出评测为准。

固定版本 llama.cpp 的视觉编码 CUDA graph 在不同尺寸裁图切换时发生过崩溃；当前启动器关闭该优化，继续使用 GPU 推理。

正式启动器另用新默认权重和模型缓存完成两次整谱转换：原生 96 小节、GGUF 64 小节；两份谱的 75／87 个和弦均保留在 GP5 与 MusicXML。安装复用已有 GPU 环境，原生缓存复用权重硬链接，GGUF 缓存不含原始 safetensors。
