结果对应 `score-support-2026-09-28` 默认权重。先用完整验证集选择模型与解码配置，再运行留出裁图和完整 PDF。分组数据、原始计数、速度和选型结果见[小节评测记录](../weights/measure_ocr/evaluation.json)。

页面结构模型先识别乐器声部、谱表和共同小节时间轴。小节模型并行读取当前及相邻小节图像，拍号／调号由独立分类器批量读取并传播，跨节延音和调弦在生成后协调。钢琴双谱表属于同一声部，五线谱＋TAB 只记一份音乐内容。独立的 `guitarocr.score/2` 保存完整结构，GP5 和 MusicXML 是导出格式。

选定配置为 **普通词表、MTP 2、每批 64 小节、16,384 tokens 上下文、BF16**。普通解码与 MTP 的选型要求：总体核心及完整匹配下降各不超过 0.1 个百分点，各语料核心匹配下降不超过 0.2 个百分点，再选择同卡实测耗时最低的配置。

与原串行模型的历史对照使用相同的 192 份曲谱、12,950 个参考小节。原串行模型 1958.73 s，本次默认模型 211.12 s，OCR 加速 **9.28 倍**。核心整小节匹配率 92.36% → 94.02%。两次模型权重不同，这个对照反映架构与重新训练后的整体结果。

约束解码使用同一模型、MTP 4 和全部 110,314 个验证小节比较：核心匹配 89.4356% → 89.4673%，完整匹配 83.3466% → 83.3484%，耗时增加 8.37%。因此 M2 语法约束保留为选项，默认关闭；页面结构的 JSON 行数和字段约束保持启用。音乐词表从训练频率选出 457 个词元，目标 token 数由 10,539,482 降至 5,477,918，本次因识别准确率下降而未采用。

导出层另用 800 份参考总谱核验：GP5 均完成写入及重新解析；MusicXML 的 392,631 个音符保留音高、起点和时值。旋律乐器由 music21 独立读取，鼓音核对 XML 时间与 MIDI 鼓件引用。这是格式保真核验，不是 OCR 准确率。

安装后的默认权重还通过实际服务队列和工作台完成混合总谱识别，验证了取消后续跑、指定小节重试、人工修改保留和项目 ZIP 恢复。浏览器实际完成分轨命名、128 种 MIDI 乐器选择、速度修改和 GP5／MusicXML 下载，音符与人工修改均保留。

数据包括原生 Guitar Pro 排版、组合总谱、独立排版器生成的多乐器作品及模拟扫描。复杂随机合成谱保留密集和弦、大跨度音高和少见鼓符等压力案例；所有组的结果均完整列出，不能把生成谱评估等同于任意真实扫描件的准确率。
