# Web 工作台

采用 FastAPI 和原生 HTML / CSS / JavaScript。无需 Node.js、npm 或前端构建。页面静态资源随 Python 包安装。

## 启动

Windows 双击 `start.bat`，Linux 执行 `bash start.sh`，首次会自动安装环境。详见 [环境安装](setup.md)。工作台会在服务就绪后自动打开。

手动开发环境使用 `uv run --no-sync guitarocr-web` 启动。不要在已安装训练依赖的环境中混用不同 extras 组合的同步命令。

可选参数：

```bash
uv run --no-sync guitarocr-web \
  --port 7860 --output output/webui --device cuda \
  --model tools/models/GLM-OCR \
  --layout-model weights/pp_doclayout_v3_score_joint_v3 \
  --layout-python tools/paddlex-venv/bin/python
```

默认只监听本机。远程 GPU 机器可以用 `ssh -L 7860:127.0.0.1:7860 user@server` 转发后，在自己电脑访问同一地址。工作台按本地个人使用设计，不包含账号系统；不要直接作为公开的多人上传服务部署。服务使用一个进程和一个任务队列，共用一份 GLM 基座，顺序执行耗时任务。

## 使用流程

1. **导入乐谱**：选择或拖入 PDF 和多张图片。列表支持上移、下移和移除，处理顺序遵循该列表。选择文件后点击「导入乐谱」才会上传；界面会显示原始文件名和已导入的总页数。PDF 和多页 TIFF 自动展开，图片按 EXIF 校正方向。每个项目最多 100 页、200 MB，单页最多 4000 万像素。
2. **调整区域**：点击自动检测，或直接手动添加框。小节框是绿色，标题信息框是蓝色，速度框是棕色。拖动移动、四角缩放，也可以输入原图像素坐标。使用画布上方的「上一页 / 下一页」、页码选择或左侧缩略图查看其他页面。选择小节后用「提前 / 延后」修正阅读顺序。不要把相邻的小节框合并；标题框保留一个即可。
3. **谱面信息**：可自动读取标题、作者、调弦、速度，也可以手动填写。没有信息裁图时，会尝试读取矢量 PDF 的文字信息。调弦按第 1 弦到低音弦排列。保存后进入下一步。
4. **校对小节**：逐小节识别，显示处理进度。对照裁图修改声部、起点、时值、音符或休止，也可以增删事件。普通 TAB 音符用「弦:品」输入，例如 `1:3,2:1`；高级文本编辑支持连音、奏法、反复记号等字段。表格编辑保留已有奏法和连音参数。每次保存都会进行音乐格式校验。
5. **导出 GP5**：生成并下载 GP5，也可下载小节文本（`score.txt`）。失败的小节暂以休止符占位，并醒目标成待检查；必须逐个保存确认后才可导出。GP5 文字采用 cp936，不可表示的字符会显示提示，原始文本保留在项目记录中。

高级文本中的 `MEASURE` 表示一个小节，下载文件为 `score.txt`。名称转换由工作台处理，旧项目可直接打开，保存和导出保留原有音乐内容。格式说明见[小节文本格式](score-text.md)。

每一步都有独立的保存结果。修改区域后，谱面信息、小节识别和 GP5 需要重新生成；修改调弦后，小节识别和 GP5 需要重新生成；修改曲名、作者、速度或变调夹保留识别与人工编辑，仅更新导出信息；修改小节后，仅 GP5 需要重新生成。修改一个小节不会自动重识别后续小节；如果修正改变了跨小节连线等上下文，也请检查相邻小节。

保存结果位于 `output/webui/<项目编号>/`，包含上传内容、各次编辑的裁图、步骤清单和 `session.json`。刷新页面可继续当前项目；地址栏的项目链接可加入书签。导入页的项目列表可重新打开其他项目，点击「上传新乐谱」导入其他文件。删除项目按钮会删除整个项目。启动路径与项目目录保持不变时，重启服务后仍能继续编辑；运行清单含本机路径，跨机器迁移请在导出页下载完整项目 ZIP，再在新工作台的导入页恢复。ZIP 内路径相对化，包含原始输入、各次保存结果与 GP5；不包含模型或机器相关的续跑签名。

## 停止、继续和小节重试

识别期间可点击「停止识别」。当前模型调用结束后停止，已完成的小节写入日志；重新打开项目后点击「继续上次识别」可复用已完成结果。服务重启会将未完成任务标记为中断。

识别完成后，可「重试待检查小节」或「重新识别此小节」。指定以外的小节和人工编辑保留。重新识别全部小节会先请求确认。跨小节连线等关系仍应检查相邻小节。

同一项目的多个页面保存时会检查版本；旧页面不会覆盖其他页面刚保存的结果。发生冲突时，先保留本页需要的文本再重新载入。

## 定位与模型

- 默认「自动识别谱面」对 PDF 和图片都运行 PP-DocLayoutV3，由模型直接给出小节位置和类型；矢量 PDF 也走这条路径。
- 只有一套版面检测权重，输出 TAB 小节、五线谱小节、混合谱小节和速度区域四类；标题区域从首个小节上方裁取，可手动调整。
- 混合谱每个小节的上下谱表合为一个框。页面和小节列表显示识别出的类型；自动模式下，可在选中框的侧栏修改该小节类型。GLM-OCR 按各小节自己的类型识别，文档汇总类型不会覆盖它。
- 手动选择全局 TAB、五线谱或混合谱，会覆盖所有小节的 OCR 类型。此时定位来源选「自动」仍优先用矢量 PDF 几何；选择「图片模型」可强制模型定位。旧两类模型的自动类型判断保留谱线规则作为兼容回退。
- 复杂布局、拍照透视和手写谱需要额外检查；分谱面评测见[模型卡](../weights/pp_doclayout_v3_score_joint_v3/README.md)。
- 「谱线几何」不需要 Paddle；信息和音符的自动读取仍需要 GLM。自动检测失败不会阻止手动画框。
- 两套 LoRA 共享一个延迟加载的基座，切换适配器和生成过程由锁保护。模型文件随仓库的 Git LFS 发布，基座的下载命令见安装文档。

## 开发和验证

```bash
uv sync --python 3.11 --extra webui --extra dev
uv run --no-sync python -m unittest discover -s tests -v
```

API / 流程测试用可控模型输出检查实际 GP5 写出与回读，覆盖编辑失效、错误校验、待检查小节、项目恢复、上传路径隔离和任务互斥。训练及模型准确率评测仍由各步骤的评测入口负责。
