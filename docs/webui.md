# 工作台使用说明

桌面端、本地网页和多人服务共用以下校对界面。启动方式见[安装说明](setup.md)。

## 导入乐谱

选择或拖入 PDF、PNG、JPG、BMP、TIFF，调整文件顺序后点击「导入乐谱」。PDF 和多页 TIFF 自动展开。每个项目最多 100 页、200 MB，单页最多 4000 万像素，所有页面合计最多 2 亿像素。

已保存的项目可以从导入页重新打开，刷新页面也会恢复当前项目。点击「导入新乐谱」开始另一份乐谱。

## 检查区域

点击「自动检测」。每个绿色框对应一个小节；混合谱的五线谱和 TAB 应放在同一个框内。蓝色谱头框用于读取曲名、作者和调弦，棕色框用于读取速度。

谱号框应完整包含谱号。移调标记框应包含移调说明，或完整的 8va／8vb 延长线；漏检时可从绘框菜单补画。C 谱号和谱号旁的小八度数字尚未验证。

选中区域后可查看裁图预览。拖动框可移动，拖动四角可缩放，工具栏支持撤销和重做。漏检时选择「＋ 小节框」补画；误检时选中后删除。侧栏的「前移」「后移」调整同页同类区域的阅读顺序，「精确位置」可输入原图像素坐标。通过缩略图或翻页按钮检查其他页面，完成后点击「保存并继续」。

「整份谱面」默认自动判断，选中小节后可单独纠正其类型。手动选择整份谱面的类型会应用到所有小节。自动检测失败时仍可手动画框。

## 校对谱面信息

点击「自动读取信息」，或直接填写曲名、作者、乐器和速度。吉他、贝斯还需核对调弦与变调夹。调弦按第 1 弦到低音弦排列，列表提供常见吉他、贝斯调弦；自定义调弦使用 MIDI 音高编号，例如五弦贝斯为 `43,38,33,28,23`。仅有五线谱时通常无法确定实际弦数和调弦，需要自行确认。

「记谱移调」可留空，使用谱面中读取的说明；没有印出的移调量需手填，例如降 B 调小号填 -2。8va／8vb 按谱中的范围作用于相应小节。变调夹品位仍需手工填写。

核对后点击「保存并继续」。修改乐器、调弦或记谱移调需要重新识别小节。钢琴和鼓组使用五线谱模式。

## 校对整份乐谱

点击「识别乐谱」，结果按阅读顺序排成整谱。识别失败或节奏冲突的小节标红，需要核对移调、谱号等信息的小节标黄。「检查标记的小节」可直接定位问题，其他小节也可点击编辑。

编辑窗口同时显示原谱和识别结果。点选音符后，用工具栏修改时值、附点、连音、休止和音高，或增删音符、整拍，支持撤销和重做。

- TAB：点击弦位，再用品位栏或数字键输入 0 至 30，`X` 表示闷音。上下键换弦，左右键换拍。
- 五线谱：点击谱表空位添加音符；选中音符后，用升降半音按钮、上下键或音高栏修改。混合谱同步调整弦位和品位。
- 鼓谱：点选鼓音后在鼓件栏更换，或向当前拍添加鼓件。

按 Delete 删除选中音符；删除最后一个和弦音后，该拍保留为休止符。工具栏可切换两个声部。「拍号、速度与起点」中可修改当前小节和音符起点，起点以四分音符拍数计算，从 0 开始。更改时值会移动后续音符。

点击「保存修改」更新整谱。切换小节、切换编辑方式或返回整谱时，也会先保存有效修改；校验失败或版本冲突时保留草稿并显示原因，也可选择「放弃修改」重新载入已保存的内容。标记小节内容无误时，可直接点击「确认此小节」。只需处理被标记的小节即可导出。

部分奏法以文字显示，绘图尚不能完整呈现推弦曲线等细节。修改这些内容或反复记号时，可切换「小节文本」，格式见[参考文档](score-text.md)。

识别期间点击「停止识别」，当前模型调用结束后保存已完成部分，稍后可继续。也可重新识别单个小节或所有待检查小节；重新识别会替换对应的人工编辑。修改小节不会自动重识别后续内容，跨小节连线需要一并检查邻近小节。

## 导出与备份

点击「导出 GP5」，生成并下载文件。文件名使用曲名，曲名为空时使用上传文件名，自动处理系统不允许的字符。也可下载 `score.txt` 查看小节文本，或下载项目备份 ZIP。在另一台工作台的导入页选择「恢复项目备份」，即可继续处理原图和已保存的编辑。

GP5 使用 cp936 字符编码，无法写入的文字会有提示；小节文本保留原文。项目备份还包含校对状态，因此需要继续编辑时应保留 ZIP。

保存结果位于 `output/webui/<项目编号>/`。地址栏链接可加入书签。删除项目会同时删除上传文件、识别结果和导出文件，操作前会要求确认。

## 保存与重新处理

| 修改内容 | 保存后需要重新处理 |
| --- | --- |
| 区域或谱面类型 | 谱面信息、小节识别、GP5 |
| 乐器、调弦、记谱移调 | 小节识别、GP5 |
| 曲名、作者、速度 | GP5 |
| 变调夹 | 五线谱和混合谱需核对音高，再导出 GP5 |
| 小节内容 | GP5 |

同一项目在多个标签页中编辑时，旧页面不能覆盖新版本。发生冲突时，先复制需要保留的修改，再重新载入项目。
