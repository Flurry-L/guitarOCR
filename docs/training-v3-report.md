# 三种谱面的扩充训练与验收（2026-09-26）

本轮完成三项任务的训练：一套 PP-DocLayoutV3 负责小节定位与谱面类型，两套 GLM-OCR LoRA 分别读取谱头／速度和小节内容，后两者共用同一 GLM 基座。历史检查点保留供回退，不增加运行时任务模型数量。默认自动识别 TAB、纯五线谱、五线谱＋TAB；用户无需先选择类型，仍可在网页上纠正单个小节。

## 数据与实际训练

全部排版使用 Guitar Pro 8 原生导出，没有使用 TuxGuitar。主语料 2,799 个曲源、8,397 份三种排版文档、30,693 页，按曲源隔离为 2,400／199／200 个训练／验证／测试来源。新增 2,000 个来源包含 1,784 个真实 GP 曲源和 216 个技巧合成谱；扫描退化是增强数据，不是真实扫描语料。

## 同条件的新旧模型比较

## 小节表示与长序列修复

小节文本使用 `MEASURE` 显示标记，前文摘要使用 `CONTEXT`；它们不是额外模型，也不区分谱面类型。显示名称通过界面和文件边界转换，不改变已训练的内部协议，不需要重新微调。本轮补齐或修复了：

- 空小节的整小节休止，前文中拍号与调号的延续。
- 可见装饰音参数、震音细分和常见推弦轮廓；不把不可见的播放参数当作 OCR 标签。
- 未知／重复元数据、重复声部与超出 GP5 两声部能力的输出检查。
- GP5 导出中的显式时间空隙、重叠事件与不可演奏音高检查，避免静默移位或夹取音高。
- 长序列中一次失败清空 swing 的问题：失败休止占位暂存前一小节 feel，仍标记需复核；正常小节省略 feel 或显式 feel=none 会切回直拍。

长序列验证定位到《Highway 61 Revisited》的第 121 小节失败后，TAB 后续约 60 小节丢失 swing。这会造成元数据匹配失败并影响 GP5 播放，不能全部说成音符错误。修复不使用标签修补预测，也不修改训练缓存或重新选测试检查点。受影响的三种排版整段重新推理；其余序列逐条审计输入、前文和失败处理完全一致后才复用，原报告与审计记录保留。

连续验证 8 个曲源、3,084 小节（每种模式 1,028）：核心匹配 81.71%→94.62%，完整匹配 75.62%→87.22%，需复核 97→23。各模式核心匹配：tab 93.58%→95.33%；notation 76.65%→92.80%；both 74.90%→95.72%。修复前候选的连续验证核心为 84.73%，其中 TAB 89.30%；旧报告未覆盖，修复后的审计／重跑单独保存。独立连续测试的新旧各 1,860 小节及基线连续验证，经逐条核验均不受这项修改影响。

这组连续验证原始输出核心匹配为 94.75%，占位处理后为 94.62%：有 4 条原始输出的音符、节奏和元数据正确，但奏法参数无效，仍被标记复核并替换为休止。完整匹配在处理前后均为 87.22%，改进没有依赖占位凑对。

3,084 个验证小节的 小节文本→GP5→重新解析检查，已编码的内容全部一致。含失败、连续失败、swing→直拍两种重置形式的回归测试也检查了实际 GP5 状态。小节文本仍不是 GP 的无损播放存档：力度符号没有按实际打印位置监督；本轮语料 trill 标签为 0，格式／导出支持不等于模型已学会识别；任意推弦控制点不完整覆盖。详细语义见 [小节文本格式](score-text.md)。

## 页面到 GP5 的验收与限制

默认版面模型自动取得小节框和类型，再由谱头及小节模型识别。真实扫描 `jixian.pdf` 新模型 17/17 小节完整匹配，旧版为 16/17；标题、作者、速度正确，全部首次解码通过，无确定性内容修补，GP5 可重新解析。

提前固定的一份保留中文曲源，三种原生排版各四小节：TAB／混合谱为 4/4；纯五线谱从旧版 1/4 提高到 3/4，仍有一小节整体低两个半音。其语法合法，自动复核标志未捕获音高错误。这些是少量流程验收，不能外推为任意真实扫描的准确率。训练主要覆盖规则吉他单轨谱，手写、透视照片、复杂多音轨总谱和同页混排需要更多数据与验证。

81 项单元测试、3 项 Chromium 浏览器测试、Ruff、差异格式检查、CUDA 环境和全部默认权重 SHA-256 校验通过。切换默认权重后再次以默认 CLI 识别 `jixian.pdf`，17/17 核心与完整匹配，标题／作者／速度正确，全部首次解码通过，GP5 可重新解析。默认权重目录：`pp_doclayout_v3_score_joint_v3`、`glm_ocr_measure_sequence_v3_lora`、`glm_ocr_document_info_v3_headers_lora`；各版本的训练配置、模型卡和机器评估记录随权重目录保留，哈希由 `weights/manifest.json` 管理。小节详细指标见[模型卡](../weights/glm_ocr_measure_sequence_v3_lora/README.md)和[评估记录](../weights/glm_ocr_measure_sequence_v3_lora/evaluation.json)。
