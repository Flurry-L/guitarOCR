# 算法与识别表现

本文说明识别流程、模型分工、训练方式与评测结果。

[项目主页](../README.md) · [乐谱数据与 M 文本](ir-and-m-spec.md) · [开发指南](development.md)

## 1. 从图中符号到完整音乐

乐谱同时包含两种信息：**当前图上画了什么（局部视觉证据），以及这些符号在整首曲子里表示什么（全局音乐语义）**。

- 例如，TAB 中的 `5` 可以直接读出品位；但下一小节延续这个音时，谱面可能只画延音弧而省略品位数字。
- 再如，闷音（`P.M.`）或延音（`let ring`）的文字标签只出现在范围开头，后续小节的虚线需要接回前面的标签才能确定含义。

GuitarOCR 将识别拆分为 **页面定位 → 局部观察 → 全谱组装**：模型读取裁图中的符号、节奏与连线端点，`scorelib` 根据音轨归属、时间顺序和音乐关系，连接相邻小节并生成完整乐谱。

![识别总览：页面定位后分别读取整谱信息和单节观察，交给音乐核心组装，再编辑和导出](assets/recognition-pipeline.svg)

*图 1：以《春日影》的页面与裁图展示数据流，其余结构为机制示意。两条读取分支采用同一 GLM-OCR 架构，各有一套任务权重。橙色关联图像，靛蓝表示网络，青绿表示音乐核心与组装结果。*

## 2. 三阶段管线详解

### 2.1 页面定位：确定音乐在哪里、属于谁

1. **多尺度版面检测**：PDF 先经 PDFium 栅格化为页面图像。微调后的 **PP-DocLayoutV3** 在整页和局部切片视图上检测 11 类乐谱区域（小节、谱头、标题、制作人员、定弦、谱号、速度、谱表标签及标注）；候选框经 MobileNetV3 质量网络评分后去重合并。
2. **谱行与音轨拓扑恢复**：
   - **同系统/同乐器关系网络**判断相邻谱行是否属于同一组同时演奏的谱行（System）或同一乐器的双谱（五线谱 + TAB / 钢琴大谱表）。
   - **信息模型与跨行接续网络**读取谱行中的乐器名、调弦等语义，并判断换行或换页后的音轨归属。
   - 程序将横向对齐、同时演奏的小节放到统一的时间轴（`timeline`）上：**音轨（Part）** 对应乐器声部，**谱表（Staff）** 是音轨内部的书写层，**声部（Voice）** 是小节内并行的节奏线。
3. **小节内和弦与指法图**：小节模型将可见和弦名关联到音符事件，独立的 ResNet18 指法图网络读取各弦品位、指法数字与横按（Barre）。

### 2.2 局部观察：把看见的内容表达清楚

小节模型每次读取 **当前一张小节图**，在 JSON Schema 约束（llama.cpp 将其转换为 GBNF）下生成包含 `state`、`voices`、`relations` 三部分的 `Observation JSON`（详见 [中间表示与 M 语言规范](ir-and-m-spec.md)）：

- **双谱独立记录**：五线谱与 TAB 同时出现（`mode = "both"`）时，每个事件分别保存 TAB 的 `notes` 与五线谱的 `notation_notes`。局部模型只记录各自可见的符号，等组谱阶段获得定弦、谱号与移调信息后，再按实际音高匹配。
- **谱面状态**：谱面状态区分 `observed`（印出并读到）、`absent`（没有新标记，沿用前节）和 `unknown`（形状尚未读清）。
- **开放端点**：延伸到裁图外的连线使用 `"left"` / `"right"` 标记端点，供后续在相邻小节中配对。

### 2.3 全谱组装：让局部观察获得音乐含义

组谱器（[`scorelib/src/observation.rs`](../scorelib/src/observation.rs)）按同一音轨、谱表的小节顺序处理观察：

1. **继承状态**：沿连续小节传播拍号、调号、谱号、八度移位、定弦与变调夹。
2. **连接关系**：根据声部、事件端点、音符身份和可见线条垂直通道（`lane`），连接跨节或节内的延音（`tie`）、击勾弦（`hammer`）、滑音（`sl`/`ss`）、闷音（`pm`）、延音线（`let`）与八度线（`ottava`）。
3. **计算音高与双谱对齐**：TAB 使用弦、品位和调弦计算音高；五线谱使用谱位、谱号、调号和同小节前序临时升降号记忆规则计算音高。双谱的两侧互相补足未印出的信息（如延音省略的 TAB 品位），若两侧音高矛盾则标记冲突供人工复核。
4. **生成乐谱表示**：输出每节的 `M` 文本与整谱 `ScoreIR`。

![跨节组装示例：缺少品位的延音在连接前音后得到品位，无标签续线在连接前节后确定为 PM](assets/observation-assembly.svg)

*图 2：两类需要跨小节解释的情况。网络分别描述每张图，组谱器在连接成立后补足音乐含义；原始观察继续保留。*

## 3. 识别网络架构

### 3.1 GLM-OCR 视觉-语言模型

信息读取与小节读取均基于 [GLM-OCR](https://github.com/zai-org/GLM-OCR) 微调，采用 **同一网络架构、两套任务权重**（`weights/information/` 与 `weights/score_ocr/`）：

![小节识别网络：图块嵌入、视觉 Transformer、空间下采样和投影、文本 Decoder，输出可见观察 JSON](assets/recognition-network.svg)

*图 3：一次小节读取的内部结构。图像转换成视觉 token 后，与任务提示一起供文本模型生成答案。*

| 环节 | 职责 | 结构参数（见 [`config.json`](../weights/score_ocr/merged/config.json)） |
| --- | --- | --- |
| 图像预处理 | 保持乐谱纵横比，控制输入像素面积，居中补白后对齐网格 | 动态分辨率，14 × 14 图块（patch multiple 28） |
| 视觉编码器 | 编码数字、谱线、符干、符尾与连线的空间关系 | 24 层 Vision Transformer，隐藏维度 1024 |
| 多模态投影 | 压缩视觉序列并映射至语言模型特征空间 | 2 × 2 空间下采样，投影至 1536 维 |
| 文本解码器 | 结合视觉 token、任务 Prompt 与语法约束自回归生成 JSON | 16 层 Transformer Decoder，隐藏维度 1536 |

### 3.2 结构改动与微调策略

| 模型 | 相对原模型的改动 | 实际更新的参数 |
| --- | --- | --- |
| **PP-DocLayoutV3** | 沿用 HGNetV2 骨干、特征融合与 Transformer 检测结构，输出类别调整为 **11 类乐谱区域** | 微调骨干后续阶段、特征融合和检测头；冻结输入卷积（stem）与 BatchNorm，骨干学习率为主学习率的 **0.05 倍** |
| **GLM-OCR 小节模型** | 保留原有层数与连接方式；**扩充音乐专用词表**，扩展词嵌入与输出层 | 在视觉塔、投影和文本解码器线性层训练 **LoRA（rank 64，alpha 128）**，同时更新 `embed_tokens` 与 `lm_head` |
| **GLM-OCR 信息 Adapter** | 在信息模型文本解码器上附加轻量任务适配器 | 仅作用于文本解码器的 **LoRA（rank 16，alpha 32）**，按谱表、谱号、速度任务动态挂载 |

### 3.3 专用辅助网络（ONNX Runtime）

页面结构、拍调号和指法图具有明确的局部几何规律，使用独立的轻量级 ONNX 模型读取（定义见 [`research/models/`](../research/models)，推理见 [`backend/src/auxiliary_onnx.rs`](../backend/src/auxiliary_onnx.rs)）：

| 任务 | 输入 → 输出 | 网络形式 |
| --- | --- | --- |
| 区域定位与质量 | 页面 → 小节 / 信息框；候选图像与几何 → 框质量 | PP-DocLayoutV3；MobileNetV3 质量网络 |
| 谱行与音轨结构 | 谱行图、相邻候选与几何 → 同系统、同乐器、跨行接续 | 卷积图像编码器 + 几何特征分类器 |
| 音乐状态 | 小节 → 印出的拍号、调号；谱号及周围谱线 → 谱号；谱行 → 谱型、弦数 | MobileNetV3 + 空间注意力、小型 CNN |
| 文字定位与归属 | 图像 → 文字区域；名称或文字位置 → 乐器类别、和弦名归属 | PP-OCRv5 文字检测、多尺度 CNN、文本 CNN |
| 指法图 | 图形裁图 → 起始品位、各弦品位、指法数字、横按 | ResNet18 图像编码器 + 多任务输出头 |

### 3.4 小节并行识别与连续批处理

单小节的视觉观察不依赖前一节的识别结果，因此各小节裁图可并行送入模型：

- 后端通过带并发上限的 FIFO 队列调度请求，底层 `llama.cpp` 使用连续批处理（Continuous Batching）共享解码计算。
- 桌面端默认并发槽位数为 **2**，服务端默认为 **4**（可通过 `--slots 1..4` 调整）。
- 在 H100 上测试《春日影》8 个 TAB 小节：模型预热后从 1 路增至 4 路，小节识别与组谱总耗时由 **4.02 秒降至 2.02 秒**（模型推理阶段由 **3.70 秒降至 1.65 秒**），且输出完全一致。
