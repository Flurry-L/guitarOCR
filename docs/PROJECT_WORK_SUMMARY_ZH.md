# GuitarOCR 项目与个人工作总结

> 整理时间：2026-08-20
> 整理依据：当前仓库代码、文档、实验报告和 Git 历史。Git 中 11 个提交均由 `lzju` 完成，因此下文把仓库中可核实的实现概括为“我的工作”。

## 一句话概括

这个项目不是单纯识别谱面上的字符，而是把 Guitar Pro/TuxGuitar 导出的吉他谱 PDF 或整页图片，恢复成包含小节、声部、节奏、弦/品、音高、延音和演奏技法的结构化事件，再写回可编辑的 GP5。我的工作已经覆盖数据生成、传统视觉模型、Guitar Pro 域适配、GLM-OCR 后训练、约束解码、GP5 写回和端到端验收；当前最值得优先解决的是整曲推理时的小节间状态传递和误差传播，同时单小节识别本身仍未达到发布门槛。

## 1. 项目目标与整体路线

项目输入是 Guitar Pro 8 风格的规则 PDF 或清晰整页图片，当前主要覆盖三种版式：

- `tab`：纯六线谱，识别弦号和品位；
- `notation`：纯五线谱，识别绝对音高；
- `both`：五线谱 + 六线谱，同时识别音高、弦号和品位。

当前 GLM-OCR 主线为：

```text
PDF / PNG
  → 页面、谱表、系统和小节切分
  → 单小节图像 + 上一小节 C2 上下文
  → GLM-OCR 0.9B + GuitarOCR v2 LoRA
  → M2 小节事件序列
  → 语法检查、音乐约束和最多三次有界自纠
  → 确定性 M2 → GP5
  → 可选 Guitar Pro 8 回渲染验收
```

旧主线则使用多个轻量 CNN 分别完成事件定位、节奏、数字/X、延音和技法识别。两条路线不是完全替代关系：CNN 路线体积小、延迟低，GLM-OCR 路线负责更强的联合上下文建模，确定性代码继续负责页面顺序、音乐约束和文件写回。

## 2. 我完成的主要工作

### 2.1 建立了从数据到 GP5 的基础工程

- 搭建 `guitarocr/` 分层包、PowerShell 一键脚本和 Java/TuxGuitar 桥接；
- 定义统一的 Score/Event IR 与后续 M2 小节事件序列，避免模型直接生成不可审计的二进制文件；
- 完成 GP 文件读取、PDF/PNG 渲染、页面和小节坐标标注、来源隔离的数据划分；
- 完成 OCR 结果到 GP5 的写入、回读、重渲染和逐事件验收；
- 对拍号、小节容量、音高—弦品关系、事件顺序和技法词表增加确定性检查。

### 2.2 训练并集成了传统视觉模型

先后实现和训练了以下模块：

- 原子符号 CNN：数字、X、音符头、休止、升降号、谱号和附点等；
- TAB 数字/X 检测器和弦/品分类器；
- `score_tab` 与 `tab_only` 两套事件定位和节奏上下文模型；
- 延音关系模型、技法多标签模型和拨弦方向模型；
- 整页版式识别、谱表/系统配对、拍号传播和小节时值约束；
- 纯 TAB 与五线谱+TAB 的整页端到端重建。

这部分工作的意义是把任务从“裁好的单符号分类”推进到“整页图片 → 有顺序的音乐事件 → 可编辑 GP5”。

### 2.3 做了 Guitar Pro 8 数据域与跨渲染器适配

- 建立 TuxGuitar、MuseScore 4、Guitar Pro 8 三渲染器的来源隔离基准；
- 自动调用固定版本 Guitar Pro 8.1.2.37，生成 `tab / notation / both` 三种 PDF 和 native layout；
- 对 Guitar Pro 矢量 PDF 读取字符框、谱线、横梁、速度和连音组信息；
- 针对 Guitar Pro 字体重新训练品位分类、节奏、延音和技法模型；
- 保证测试曲不回流训练集，并把回归成绩与独立泛化成绩分开报告。

### 2.4 完成了 GLM-OCR 后训练与端到端管线

这就是项目中明确存在的“后训练”工作，具体是对预训练 `GLM-OCR 0.9B` 进行监督微调（SFT）和 LoRA 域适配，而不是从零训练模型。

主要内容包括：

- 使用 LLaMA-Factory 的 LoRA 训练流程；
- 为 RTX 20 系显卡采用 FP16，关闭 BF16；
- v1 只训练语言侧 LoRA，用于验证 M2 输出语法和任务可行性；
- v2 同时训练视觉塔和语言 Transformer 的 LoRA，使模型适配细小品位数字、音符头和技法标记；
- 设计 M2 监督目标，使不同版式只预测图中可见的字段；
- 引入长尾 hard-case 训练文件，提高推弦、滑音、击勾弦、多声部等样本的权重；
- 对输出增加结构化指标、运行签名、断点续评和严格 release gate；
- 最终把一个合并 LoRA adapter、推理入口、GP5 写回和官方 GP8 回渲染串成可复现流程。

### 2.5 建立了严谨的实验与发布口径

- 训练、验证、测试按原始曲目 SHA 隔离，而不是随机拆小节；
- hard-case 目标曲只作为回归验收，不冒充独立泛化结果；
- 将几何切分、单小节语义、整曲推理和 M2→GP5 写回分别评估；
- 明确区分“图中不可见、理论上不能唯一恢复”的信息，例如纯五线谱的原作者弦位；
- release gate 同时检查语法、音乐约束、核心字段、节奏、音符字段和逐技法 F1，不用训练 loss 代替端到端准确率。

## 4. M2 和 C2：当前怎样表示小节及其联系

M2 是一个小节的可解析事件序列。例如：

```text
M2 time=4/4 tempo=100 key=CMajor | V0{@0:q:s1f3p67 @960:q:r}
```

它保存小节元数据、声部、事件起点、时值、休止、弦/品、音高和技法。

为了建模小节之间的连续性，所有非首小节都附带一个 `C2` 上下文。当前 `C2` 的生成方式是：

- 保留上一小节的拍号、速度、调号和 triplet feel；
- 每个声部只保留起点最晚的最后一个事件；
- 去掉上一小节其余事件和大部分结构信息；
- 训练时 `C2` 来自上一小节真值；
- 整曲推理时 `C2` 来自上一小节已经接受的预测。

这个设计比把完整上一小节塞进提示更省 token，也确实给延音和声部连续性提供了信息，但它正是当前跨小节瓶颈的核心位置。

## 5. 当前结果

### 5.1 数据与页面几何

- v2 数据集：2,000 首、149,126 个唯一小节、447,378 个目标，标签门禁失败为 0；
- 200 首来源隔离测试曲中，`notation / both / tab` 三种版式均恢复 15,304/15,304 个小节；
- 这说明页面到小节的几何切分已经很稳定，但该指标不代表音符语义识别准确率。

### 5.2 最终 step 27,403 LoRA 的 3,000 小节测试

| 模式 | 样本 | 语法有效 | 约束有效 | 完全一致 | 核心字段整小节一致 | 节奏整小节一致 | 音符字段整小节一致 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| `tab` | 1,000 | 99.9% | 99.9% | 69.6% | 84.9% | 92.0% | 87.9% |
| `both` | 1,000 | 99.6% | 89.2% | 63.3% | 77.4% | 90.9% | 80.7% |
| `notation` | 1,000 | 99.7% | 99.7% | 44.0% | 60.4% | 93.4% | 63.1% |
| 总体 | 3,000 | 99.73% | 96.27% | 58.97% | 74.23% | 92.10% | 77.23% |

其中 `tab` 对齐音符的弦号准确率为 96.53%，品位准确率为 96.04%。总体技法 F1 为 84.51%，和弦名、dead、ghost、拨弦方向等较好，泛音、推弦、滑音、自由文本以及部分跨事件技法仍偏弱。严格 release gate 没有通过，因此该 adapter 应表述为“可复现实验基线”，不能表述为已经完成无误转录。

### 5.3 整曲独立验收

checkpoint-16000 曾在两首未进入训练集的纯 TAB 曲上完成整曲验收：

- 63 小节曲：核心字段 98.41%，节奏 100%，弦/品均 99.88%；
- 180 小节 Lead 轨：核心字段 96.11%，节奏 97.22%，弦 96.92%，品 96.54%。

这证明端到端链路能够工作，但样本只有两首、仅覆盖纯 TAB，而且使用的是中间 checkpoint。它不能取代最终 3,000 小节测试，也不能证明其他版式已经达到同样水平。

### 5.4 M2 写回 GP5

- 测试真值的 `tab` 与 `both` 均为 15,304/15,304 小节往返一致；
- `notation` 为 15,296/15,304；8 个差异来自图中不可见且源文件本身缺少可继承同弦前音的孤立 tie；
- 实际预测的三连音和部分技法写回仍有损失，说明视觉识别之外，writer 也还有独立问题。

## 6. 当前瓶颈：推理时的小节间联系

### 6.1 我的判断

如果目标是让“整首曲”稳定可用，那么小节间联系确实是当前的关键架构瓶颈，主要涉及延音、滑音、hammer/pull-off、跨小节技法线、声部连续性、跨系统/跨页连线和导航后的真实播放顺序。

但它不是唯一瓶颈。最终 3,000 小节测试中，`notation` 音高准确率约 80.01%，`both` 约束有效率只有 89.2%，节奏整小节一致率总体为 92.1%，多类技法也未达到 90% F1。因此应更准确地说：

> 单小节识别仍有明显误差；当它进入整曲自回归推理后，当前 C2 机制又会放大这些误差，并且不足以表达完整的跨小节关系。

### 6.2 已确认的具体问题

1. **训练和推理的上下文分布不一致。**训练数据中的 C2 来自上一小节真值；整曲推理中的 C2 来自上一小节预测。这是典型的 exposure bias，前一小节一旦识别错，错误可能继续影响后面的小节。

2. **当前 3,000 小节正式评测没有测到这种误差传播。**评测脚本直接读取测试清单里的 `previous_context`，而该字段由上一小节真值生成。它衡量的是“真值上下文下的单小节能力”，不是“上一小节预测上下文下的整曲 rollout 能力”。

3. **C2 状态过于紧凑。**每个声部只保留最后一个事件，没有显式保存每根弦最后仍在发声的音、待完成的 tie/slide/hammer 关系、开放的技法区间、上一小节末尾置信度等信息。

4. **图像也按单小节裁切。**跨小节、跨系统或跨页的连线可能在裁切时只留下半段，模型即使有上一小节文本，也缺少边界两侧的完整视觉证据。

5. **约束主要验证单小节是否合法。**它能检查字段、顺序、时值和弦品关系，却还不能充分判断整首曲中的连接关系是否前后闭合。

6. **当前推理一旦接受一个“合法但语义错误”的小节，就会把它作为下一小节上下文。**语法/约束有效不等于内容正确，最多三次自纠也主要针对合法性错误，而不是文档级语义一致性。

## 7. 建议的优化路线

### P0：先建立真正的整曲连续推理评测

这是优先级最高、成本最低的一步：

- 在 200 首来源隔离测试曲上按真实顺序连续推理；
- 上一小节使用模型预测生成 C2，不使用真值；
- 同时跑三组对照：无上下文、真值 C2、预测 C2；
- 分别统计首小节、普通边界、系统边界、跨页边界和含 tie/slide/hammer 的边界；
- 记录错误从第几小节开始、连续影响几小节，以及恢复正常所需距离。

这样可以直接得到“oracle C2 与 rollout C2 的差距”，判断跨小节误差传播究竟占总误差多少。

### P1：把 C2 改为显式的文档状态

建议新状态至少保存：

- 当前有效的拍号、速度、调号和调弦；
- 每个声部的小节末游标和最后事件；
- 每根弦最后一个可延续音的弦/品/音高；
- 尚未闭合的 tie、slide、hammer/pull-off 和其他跨度技法；
- 开放中的 palm mute、let ring 等区间状态；
- 上一小节预测置信度和约束修复记录。

这样上下文表达的是“音乐状态”，而不只是上一小节最后一段 M2 文本。

### P2：加入边界视觉信息

可以在不改大模型的前提下尝试：

- 当前小节图 + 上一小节末尾窄条；
- 对跨系统边界提供上一系统尾部和下一系统头部的双图；
- 或使用相邻两小节重叠窗口，分别生成后再对重叠事件做一致性合并。

这会直接补充跨小节连线的视觉证据。

### P3：让训练见到“有错误的上一小节”

- 用当前模型离线生成训练曲的 rollout 上下文；
- 按一定概率混合真值 C2、预测 C2、轻度扰动 C2 和缺失 C2；
- 对上一小节常见的弦、品、时值、tie 和技法错误做定向噪声；
- 训练模型在上下文不完全可靠时优先相信当前图像，并学会恢复。

这相当于 scheduled sampling/DAgger 思路，可以缩小训练—推理分布差异。

### P4：增加文档级二次校正

第一遍仍逐小节快速生成，第二遍再用整曲约束或小型事件 Transformer 处理：

- tie 的目标音高/弦号必须能在前文找到；
- slide、hammer/pull-off 的方向和端点必须合理；
- 技法跨度必须成对闭合；
- 声部和小节容量保持连续；
- 对低置信度边界保留多个候选，用动态规划或 reranker 选择全曲一致性最高的路径；
- 必要时同时参考前一小节和后一小节，避免只能单向传播。

这一步更适合在结构化事件上完成，不一定需要再引入一个约 1B 参数的大模型。

### P5：并行修复单小节和 writer 问题

跨小节方案之外，仍应继续处理：

- `notation` 音高识别；
- `both` 的音高—弦品冲突；
- 三连音/连音组、密集和弦弦号分配；
- hammer、vibrato、bend、slide、harmonic 和自由文本；
- M2→GP5 对三连音和部分技法的无损写回。

## 8. 推荐的近期里程碑

1. **M3.1：连续推理基准。**完成 200 首测试曲的无上下文/真值 C2/预测 C2 对照报告。
2. **M3.2：显式跨小节状态。**实现 per-voice、per-string、pending-link 的新上下文格式，并保持向后兼容。
3. **M3.3：边界训练。**构建跨小节连线 hard-case 数据，加入预测上下文和扰动上下文训练。
4. **M3.4：文档级校正。**实现双向边界检查和候选重排，单独报告 tie/slide/hammer 的跨小节 P/R/F1。
5. **M3.5：发布验收。**同时通过单小节 release gate、整曲 rollout 指标和预测 M2→GP5 回读验收。
