同日后续的开源审核将 Pillow 升至 12.3，并整理共用几何与模型池逻辑；44 项测试、2 项浏览器回归及真实 PDF / 图片示例通过，细节和剩余问题见 [审核记录](open-source-audit.md)。下文原始记录和 `validation-example.json` 保留原验证时的数值。

## 安装与软件行为

- Linux x64 / Python 3.11：在独立目录实际运行一键 CPU 安装、重复安装、CPU 切换 CUDA、环境与 SHA-256 检查、启动。默认安装目录也完成 CUDA 安装。Paddle CPU 使用真实发布权重完成图片定位；新安装的 CUDA 环境完成 PDF 和图片到 GP5 的实际推理。
- 安装验证复用了本机 GLM 基座文件，没有重复下载约 2 GB 的模型；另行核对了 Hugging Face 固定 revision 的文件大小与远端 LFS SHA-256，均与安装清单一致。
- 全新轻量开发环境：按 uv.lock 安装，仅启用 webui / dev，确认没有 Torch；37 项核心、API、数据构建、评测上下文及安装器测试通过（含补充的 Linux 立即重启回归）。
- Chromium：两项浏览器场景覆盖四页 PDF、翻页、拖框、信息与音符编辑、旧标签页冲突、失败检测后手动画框恢复、GP5 下载和新文件导入提示。
- 真实浏览器与模型：上传示例 PDF、自动定位和识别、逐小节人工校对、下载 GP5，并重新读取验证标题与小节数量，全部通过；浏览器没有 JavaScript 错误。
- wheel 构建与静态资源、阶段配置、原生源码完整性检查通过；安装 wheel 后从仓库外验证各阶段导入、WebUI 路由与前端模块可用。
- Windows 安装脚本与原生 MSVC 编译尚未在本机实测，已提供对应 CI 入口。CI 未运行前不能将配置存在视为平台验证通过。

## 真实模型示例

模型文件、基座 revision、输入哈希和完整指标见 [机器可读记录](validation-example.json)。自编 First Steps 只有四小节，不是代表性测试集。

环境：Linux x64、Python 3.11.14、NVIDIA H100 80 GB，Torch 2.14.0、Transformers 5.8.0、PEFT 0.18.1。GLM 使用 GPU，图片版面检测使用独立 Paddle CPU 环境。输入与参考输出位于 examples/。

| 输入 | 检测小节 | 完整流程耗时 | GP5 写出 | 完全匹配小节 |
| --- | --- | --- | --- | --- |
| demo.pdf | 4 / 4 | 16.0 秒 | 成功 | 0 / 4 |
| demo.png | 4 / 4 | 16.9 秒 | 成功 | 3 / 4 |

两个案例合计的 PyTorch 峰值已分配显存约 2.26 GiB；这不包含全部 CUDA 驱动、预留显存和 Paddle 内存，不能直接视为最低显存要求。耗时包含各次模型加载，其他设备和曲谱长度会不同。

PDF 的自动结果包含多余声部休止和首小节识别错误；图片首小节把拍号中的数字误读为音符。结构校验都通过，说明语法和约束校验无法发现所有识别错误。案例在未人工修改时统计，未剔除失败小节，GP5 成功写出也不等于转录正确。

这些结果说明应保留逐步校对流程，并分别报告定位、音符、节奏及整谱效果。正式公开模型的总体准确率、独立测试集效果、消费级显卡耗时和最低资源要求仍待补充。训练损失、发布门槛以及此前四页 95 个检测框，都不能代替这些指标。

复现命令见 [训练与评测](training.md)。如果模型、示例、裁图规则或依赖发生变化，应重新生成记录。

## 2026-09-26：三种谱面的版面模型

新增统一 PP-DocLayoutV3，使用 Guitar Pro 8 原生渲染的 7,003 页训练、1,196 页验证，训练 12 轮并选用第 8 轮检查点。独立测试集为 100 个来源、1,123 页；小节 AP@[0.50:0.95] 为 TAB 98.76%、五线谱 93.68%、混合谱 97.90%。旧稀疏 TAB 验证集的小节数完全正确页面为 987/989（旧模型 985/989）。完整版本签名、逐类指标和旧模型对照见[模型卡及机器记录](../weights/pp_doclayout_v3_score_multimode/README.md)。

默认 Paddle CPU 环境实际通过三种 GP8 样例的自动类型判断和小节定位，每份均为 4 小节。`jixian.pdf` 使用默认模型和自动类型判断得到 17 个覆盖上下谱表的小节框，旧模型为 35 个框。新增版面模型未重跑本页历史 GLM-OCR 转录结果，不能将版面指标当作 OCR 准确率。

## 2026-09-26：模型直接输出谱面类型

在上述 GP8 数据上将小节监督拆为 `measure_tab`、`measure_notation`、`measure_both`，保留 `tempo_region`，继续微调 8 轮，按验证集选择第 7 轮。该阶段默认模型为 `weights/pp_doclayout_v3_score_typed`，现已由下文扩充训练版替换。同一来源三种排版仍保持相同的数据划分，图像与框坐标未改变。

独立测试 1,123 页的页面类型全部正确；IoU 0.50 成功匹配的 25,749 个小节类型全部正确，真实小节数为 25,758。小节 AP@[0.50:0.95] 为 TAB 99.48%、五线谱 94.35%、混合谱 97.95%。旧稀疏 TAB 验证集 AP 为 98.66%，但数量完全正确页面从上一版 987/989 降至 979/989。完整指标、来源哈希、初始化及训练记录见[模型卡](../weights/pp_doclayout_v3_score_typed/README.md)和[机器记录](../weights/pp_doclayout_v3_score_typed/evaluation.json)。

默认 CPU 环境、自动谱面类型与自动定位来源下，三份 GP8 矢量 PDF 各正确检测 4 个小节，扫描 `jixian.pdf` 正确检测 17 个混合谱小节。禁用谱线类型分类函数后仍通过，确认类型来自模型；已目视检查扫描样例叠框图。

62 项单元测试、3 项 Chromium 浏览器测试、Ruff、环境与 SHA-256 检查通过。测试覆盖不同类型的小节提示词、上下文切换、编辑校验、自动模式下逐框类型纠正与刷新恢复。GLM-OCR 权重未改变，这一轮没有重新评测真实音符转录准确率。

## 扩充训练版版面模型

当前默认为 `weights/pp_doclayout_v3_score_joint_v3`。在新增来源后的固定测试 2,164 页上，新旧模型统一使用 `--postprocess --threshold 0.25`：四类 AP 干净 94.81%→95.30%，扫描退化 94.91%→95.67%；数量完全正确页分别 2146→2148 和 2145→2151。三种类型的页面准确率均为 100%。先按验证集选择第 4 轮，再运行独立测试；干净验证数量正确页 2324→2322 的轻微退步也保留。详细对照和 CPU 验收见[模型卡](../weights/pp_doclayout_v3_score_joint_v3/README.md)。

## 多语言谱头修复版

默认谱头适配器为 `weights/glm_ocr_document_info_v3_headers_lora`。固定混合测试 1,536 条中，作者字段 613/768→761/768，标题 764→765/768，调弦 767→768/768，速度均为 768/768。新增副标题的干净／退化测试均正确；原有测试作者 585→581/588 的退步保留在[模型卡](../weights/glm_ocr_document_info_v3_headers_lora/README.md)。本版通过真实中文谱头检查，初版 Info v3 的副标题误作作者问题另留失败记录；单页验收不当作真实扫描准确率。

## 小节扩充训练版与 swing 连续状态修复

默认使用 `weights/glm_ocr_measure_sequence_v3_lora`。固定独立测试 1,800 小节（正确裁图／正确前文）的核心匹配 80.11%→88.89%、完整匹配 68.83%→80.44%；另外 8 个固定测试曲源的 1,860 连续小节核心 90.38%→95.32%、完整 85.54%→93.66%。核心匹配同时包含小节元数据、节奏和音符字段，不能只称为音符准确率。

连续验证暴露了失败后 swing 前文丢失；修复失败占位状态后，受影响曲源的三种排版从首小节重新推理，其余预测先逐条审计才复用，旧报告保留。3,084 小节验证核心 81.71%→94.62%、完整 75.62%→87.22%，三种模式均改善；原始输出核心为 94.75%，4 条无效奏法输出仍需复核。独立测试权重没有重新选择，未用标签修补预测。完整指标和剩余错误见[扩充训练报告](training-v3-report.md)。

最终默认 CLI 真实扫描验收再次通过：`jixian.pdf` 自动识别混合谱、17/17 小节完整匹配，无重试或确定性修补，标题／作者／速度正确，GP5 可解析。81 项单元测试、3 项浏览器测试、Ruff、差异格式检查、CUDA 环境和全部默认权重哈希校验通过。

## 小节文本的显示名称

工作台高级编辑、下载及格式说明使用 `MEASURE`（小节）／`CONTEXT`（前文），下载文件为 `score.txt`。名称在显示、编辑保存及导出边界转换，旧项目、续识别用的内部协议和权重均保持兼容；没有重新微调。82 项单元测试和 3 项浏览器测试通过，覆盖可读文本编辑、下载、旧项目读取和跨目录恢复。模型提示词、内部解析／格式化、识别器、评估代码及权重哈希与改名前一致；真实 17 小节转换后导出的 GP5 与原结果逐字节一致。
